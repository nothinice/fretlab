FretLab: обзор публичных GitHub-проектов и применимых идей
Проверено 16 ноября 2026. Исследовательский отчёт, не правки приложения.

ОХВАТ И УРОВЕНЬ ПРОВЕРКИ
GitHub search_repositories по fretlab вернул 59 совпадений имени/описания.
Это не 59 гитарных приложений: среди результатов есть форки, пустые проекты,
наш репозиторий и не относящееся к гитаре ПО для fluorescence resonance energy
transfer. Например pgrobasillobre/FretLab — расчёт переноса энергии, не гриф.
Ни один поиск не гарантирует нахождение вообще всех похожих приложений.
Ниже 12 наиболее содержательных проектов из рассмотренной выборки.

Проверка A: прочитаны README, дерево и конкретные исходники функции.
Проверка B: прочитаны README/метаданные; реализация отдельных функций не проверена.
Самостоятельно не собирал и не проигрывал эти приложения. Присутствие функции
в исходниках не подтверждает удобство, точность распознавания или качество обучения.
Даты/лицензии — наблюдение текущего репозитория, не оценка юридической совместимости.

ДРУГИЕ FRETLAB

1. felix-zailskas/fretlab — самый содержательный кандидат на тот, который видел пользователь.
Репозиторий: https://github.com/felix-zailskas/fretlab
Демо: https://fretlab.studio/
MIT, не archived. Сам автор позиционирует как справочник для среднего/продвинутого
гитариста, не курс. Note Map, CAGED Scale Positions, Chord Shapes, параллельные лады,
редактор прогрессии, длительности, метроном, настраиваемое предвосхищение смены.
Главная идея: текущий аккорд показан заливкой, будущие опоры — контурными кольцами
за 1–8 долей. Общая нота остаётся на месте, но меняет цвет, если меняется её роль.
Совпадения соседних CAGED-позиций выделены как общая область. Можно скрывать струны.
Для нас: добавить именно предварительное видение смены и связность позиций;
базовые гаммы/аккорды/цвета у нас уже есть.
A, проверены:
https://github.com/felix-zailskas/fretlab/blob/main/src/theory/chordPreview.ts
https://github.com/felix-zailskas/fretlab/blob/main/src/components/Fretboard/PreviewRings.tsx
https://github.com/felix-zailskas/fretlab/blob/main/src/components/Fretboard/useMarkerTransitions.ts
https://github.com/felix-zailskas/fretlab/blob/main/src/components/ProgressionLane.tsx
Форк jottinger/fretlab не считать отдельной продуктовой идеей.

2. simoz/fretlab
Репозиторий: https://github.com/simoz/fretlab
Демо из README: https://simoz.github.io/fretlab/
MIT, не archived. Шесть разделов: гаммы, аккорды, прогрессии, трезвучия,
репертуар, метроном. Есть генерация расположений с выбором обращения,
групп струн, guide tones, целевых нот, совместимых мелодических материалов.
Контекстные ссылки на записи сопровождаются пояснением, что слушать, и пометкой
точного/частичного/вариантного соответствия прогрессии.
Для нас: связать собственный этюд с конкретным музыкальным явлением и коротким
заданием на слушание; на грифе включать только общие ноты или 3/7 текущего аккорда.
A: https://github.com/simoz/fretlab/blob/main/assets/app.js
README подтверждает репертуар; сами анализы песен не проверены музыкально.
Форк kpanic/fretlab не считать независимым приложением.

3. Aaronv1983/fretlab
https://github.com/Aaronv1983/fretlab
Клиентское приложение с очередью упражнений на сегодня, самооценкой и историей.
В коде nextReview есть упрощённый SM-2; при высокой самооценке рабочий темп
увеличивается на 5 BPM до цели. Список на сегодня выбирает до пяти due-упражнений.
Дополнительно справочники гамм/аккордов, круг квинт, тюнер, предположение тональности.
Для нас: экран «Сегодня» из слабых мест и заданий на возвращение; темп повышать
по решению ученика/преподавателя. Самооценка не равна измеренной точности игры.
A: https://github.com/Aaronv1983/fretlab/blob/main/src/App.jsx
README предлагает свободное использование разговорной фразой; отдельной
стандартной лицензии в рассмотренном дереве нет. Не брать исходники автоматически.

4. o-icho/fretlab
https://github.com/o-icho/fretlab
Демо из метаданных: https://fretlab-opal.vercel.app
Четыре браузерных инструмента: аккорды, метроном, тюнер, транспозитор;
статьи из локального Markdown, статический экспорт и Android-обёртка.
Для нас: полезный продуктовый принцип «объяснение ↔ соответствующий инструмент»,
а не необходимость переносить весь стек. B, README и метаданные.

Также найден wormusic/FretLab: гаммы, диатонические аккорды, позиции и цвета;
по README существенной новой идеи сверх нашего текущего грифа не выделено.
https://github.com/wormusic/FretLab
Другие точные совпадения: TechnicallyAustin/Fretlab (сессии/рутины/учётная запись),
yuri-r2/fretlab, SeokhyeonLeeMed/fretlab, 8p4dev/FretLab и другие. Их наличие
подтверждено, но нельзя утверждать, что пользователь видел какой-то конкретный.

ПОХОЖИЕ ПРИЛОЖЕНИЯ

5. FretFlow — iecg/fretboard-app
https://github.com/iecg/fretboard-app
Демо: https://iecg.github.io/fretboard-app/
AGPL-3.0 по метаданным, не archived. Прогрессии и сопровождение, визуальное
голосоведение, три слоя нот (аккорд/гамма/вне гаммы), CAGED и 3NPS, фокус
на основном тоне, guide tones или общих нотах. Есть режимы одной/двух струн,
диатонические интервальные пары, визуальные подсказки приближения смены.
Для нас: один и тот же C → F можно проходить на разных уровнях ограничения:
одна струна → общий звук → ближайшая опора → 3/7 → мотив между опорами.
A:
https://github.com/iecg/fretboard-app/blob/main/packages/core/src/shapes/practicePatterns.ts
https://github.com/iecg/fretboard-app/blob/main/packages/fretboard/src/store/practiceLensAtoms.ts
https://github.com/iecg/fretboard-app/blob/main/packages/fretboard/src/progressions/voiceLeading.ts
Простые алгоритмы близости высот сами по себе не гарантируют удобство рук.

6. Open Guitar Practice — stas-polukeev/OpenGuitarPractice
https://github.com/stas-polukeev/OpenGuitarPractice
MIT, не archived. Задания найти ноту/ступень, последовательности, интервалы,
слух в тональном контексте, память мелодии, ритм и связанные справочные страницы.
В коде слуха трудные/просроченные ступени получают больший вес; попытки и
путаница между ответами сохраняются; мелодии растут от двух нот до пяти.
Для нас: постепенно расширять узнаваемые рисунки и возвращать конкретную
ошибку, например «3 и 5 путаются», вместо общей отметки «пройден слух».
A: https://github.com/stas-polukeev/OpenGuitarPractice/blob/main/frontend/js/theory/ear-curriculum.js
Также README описывает PWA/offline и iOS. XP/серии не нужны нашему согласованному
подходу; фиксированные пороги mastery — выбор автора, не доказанный стандарт.

7. Fretwise — csenkey/fretwise
https://github.com/csenkey/fretwise
Генератор упражнений по выбранному аккорду, трёхнотные группы, хроматические
подходы и окружения, пропуск струн; уроки ведут в инструменты с заполненными
параметрами. README также описывает рисунки ритма, лики, сопровождение,
постепенное увеличение темпа, MIDI/PDF, ссылки с состоянием и PWA.
Для нас: библиотека небольших проверенных преобразований мотива, доступных
из урока сразу на нужной гармонии; отдельная настройка числа повторов и темпа.
A для упражнений:
https://github.com/csenkey/fretwise/blob/main/src/main/java/org/example/arpeggiogenerator/ExerciseGenerator.java
Остальные перечисленные функции — README + наличие соответствующих модулей.
README «for educational purposes» не задаёт стандартную открытую лицензию.
Автоматически сгенерированное соло не считать учебно проверенным репертуаром.

8. Guitar Lab — RezixDev/Guitar-Lab
https://github.com/RezixDev/Guitar-Lab
Библиотека технических упражнений с категорией, уровнем, темпом, конкретным
рисунком, направлением штриха и подсказкой. Есть гаммы, аккорды, поиск нот,
нотный редактор, тюнер; случайный выбор практики по категориям.
Для нас: карточка упражнения «зачем → точный рисунок → типичная ошибка → темп
и критерий», а не случайные ноты, названные персональным планом.
A: https://github.com/RezixDev/Guitar-Lab/blob/main/src/features/practice/data/exercises.ts
README пишет MIT, но отдельного LICENSE в прочитанном дереве не обнаружено;
документировать как заявление README, не как проверенную разрешительную лицензию.

9. Open Fretboard — ArthurNTI/open-fretboard
https://github.com/ArthurNTI/open-fretboard
Демо: https://arthurnti.github.io/open-fretboard/
GPL-3.0-or-later в исходниках. Справочник, поиск аккорда по точкам, реальные
строй/каподастр, левша, вертикальный гриф, PWA. Поиск расположений учитывает
число пальцев, размах, открытые струны под баррэ, бас и возможные пропуски тонов.
Для нас: в песочнице поиск подходящего расположения по струнам, диапазону
и басу; ясное объяснение пропущенного тона. Это дополнение к уже имеющемуся
идентификатору, а не второй анализатор рядом.
A: https://github.com/ArthurNTI/open-fretboard/blob/main/src/theory/voicings.ts
Ограничение поиска: описанный алгоритм требует основной тон в басу;
не выдавать это за универсальный генератор всех обращений.

10. FretForge — louiecai/fretforge
https://github.com/louiecai/fretforge
MIT, не archived. Несколько гамм/аккордов поверх одного грифа, раздельный
или смешанный цвет пересечений, произвольные настройки; PNG и JSON-состояние.
Для нас: сравнение «до/после», сохранение собственной схемы и ссылка/изображение
для преподавателя. Наложение множества гамм не делать стартовым экраном новичка.
A: https://github.com/louiecai/fretforge/blob/main/src/components/FretboardVisualizer.tsx
В этом файле подтверждены обработчики PNG/JSON. src/lib/ExportImport.ts пустой —
само имя файла не доказывает существование функции; реализация найдена в компоненте.

11. FretFlow — Lfrangt/fretflow-ui (другой проект, не iecg)
https://github.com/Lfrangt/fretflow-ui
Демо: https://www.fretflow.io
Код MIT; сторонние компоненты и медиа имеют свои условия. Прогрессия с
соединёнными аппликатурами, закрепление выбранного расположения на конкретном
шаге, сравнение соседей, loop пары аккордов. Импорт ChordPro/MusicXML/Guitar Pro,
анализ медиа и редактируемый черновик транскрипции заявлены README.
Для нас: выбрал форму C → система предлагает близкие F → закрепил свой
вариант → сыграл и сравнил; собственные выборы сохраняются для каждого такта.
A для закрепления/сравнения:
https://github.com/Lfrangt/fretflow-ui/blob/main/components/fingering-panel.tsx
Транскрипция прямо названа Beta; её качество здесь не проверялось.

12. Scale Teacher — SeanSnaider/Guitar-Scale-Tool
https://github.com/SeanSnaider/Guitar-Scale-Tool
Демо из README: https://scaleteacher.onrender.com/
Микрофонный FFT-анализ аккордов, тренировка гамм и слуха, прогресс;
ИИ-планы и варианты прогрессий требуют отдельного API-ключа пользователя.
Сам README описывает ограничения распознавания: гармоники одиночной ноты
могут выглядеть как мажорный аккорд, бас/обращения теряются в chroma-векторе.
Для нас: полезный ориентир для отдельного будущего прототипа слушающего
тренажёра; не обещать сейчас оценку реальной игры по такому детектору.
A для хранения прогресса; распознавание — README + дерево тестов, не аудиобенчмарк:
https://github.com/SeanSnaider/Guitar-Scale-Tool/blob/main/frontend/src/store/progress.ts
Фиксированный критерий «три прохода при 120 BPM» не переносить в наш курс:
это не универсальная мера освоения.

ЛУЧШИЕ ДОБАВЛЕНИЯ ДЛЯ НАШЕГО ТЕКУЩЕГО ПРОТОТИПА

Первый приоритет — смена аккорда как понятное событие на грифе.
Показывать «сейчас C / дальше F», общую C, движение E→F, будущую опору контуром
за одну долю. Ученику сначала предсказать и выбрать ход, потом услышать и сыграть.
Те же функции работают в упражнениях и свободной прогрессии. Источники: Felix,
iecg; нашу методику и музыкальные примеры всё равно проверять по литературе.

Второй — упражнение с параметрами, а не ещё один каталог.
Один мотив: целиком, только на одной струне, на паре струн, по терциям,
со сменой ритма, с выходом на 3 нового аккорда. Ограничения менять по одному.
Источник идей: iecg, Fretwise, Guitar Lab. У нас уже есть 12 фиксированных
упражнений и вариация последней ноты; новизна здесь — переносимый набор правил
и разные задания на том же музыкальном материале.

Третий — «Сегодня» из реальных слабых мест.
Вернуть незакреплённый переход, одну путающуюся ступень, прошлый этюд без
подсказок; завершить маленькой музыкой. Отдельно хранить экранную точность
и самоотчёт игры. Источники: Open Guitar Practice, Aaron FretLab.
У нас уже сохранение темпа/заметок и планы; не нужно снова делать просто журнал.

Четвёртый — работа преподавателя со схемой.
Сохранить сцену грифа/прогрессию/темп/выбранные струны в ссылку, открыть как
задание, отправить свою версию; экспорт рисунка. Источники FretForge и Fretwise.
У нас JSON и печать уже есть; новая ценность — воспроизводимая общая ссылка.

Пятый — музыкальные примеры в контексте.
К собственной миниатюре добавить авторскую запись преподавателя и одну цель
слушания. Для сторонних произведений — проверенная ссылка на запись и точный
участок/явление; не считать похожую гармонию точной транскрипцией.
Источник интерфейсной идеи: simoz/FretLab.

Позже: поиск и закрепление удобных voicings, PWA/offline, левша/вертикальный
режим, альтернативные строи. Микрофонная полифония, автотранскрипция,
ИИ-генератор целого курса и десятки декоративных тем сейчас проигрывают
по полезности хорошему уроку C → F и предсказуемой практике.

Этот обзор показывает решения других разработчиков, а не доказывает
эффективность их педагогики. Звёзды GitHub и количество функций не использованы
как оценка качества обучения. Никакой чужой код/контент в наш проект не переносился.
